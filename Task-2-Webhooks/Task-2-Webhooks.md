
Task 2: Documenting Webhooks & Asynchronous Events
1. Introduction
Webhooks allow an application to receive automatic notifications when an event occurs on a server. Instead of repeatedly requesting information from the server, a developer provides a webhook URL, and the server sends an HTTP request to that URL when a specific event occurs.
For example, an e-commerce system may send a webhook when a new order is created or when a payment is completed.
This documentation explains how developers can subscribe to webhooks, receive webhook events, and verify webhook signatures using HMAC SHA256 to ensure that the payload came from the expected server and has not been altered.
2. Webhook Subscription Process
Before receiving webhook events, a developer must create a webhook subscription. The subscription tells the server which events the application wants to receive and where those events should be sent.
Step 1: Provide a Webhook URL
The developer provides a publicly accessible URL where the server can send webhook notifications.
Example:
https://example.com/webhooks/orders
Step 2: Select Events
The developer selects the events they want to receive. For example:
order.created
order.updated
payment.completed
Step 3: Create the Subscription
The application sends a subscription request to the server.
Example:
POST /webhooks/subscriptions
Example request:
{
  "url": "https://example.com/webhooks/orders",
  "events": [
    "order.created",
    "payment.completed"
  ]
}
Step 4: Receive Webhook Events
When one of the selected events occurs, the server sends an HTTP request to the registered webhook URL.
Example:
POST /webhooks/orders
The request contains the event information and a signature that can be used to verify that the webhook came from the server.
3. Webhook Payload and Signature
When the server sends a webhook event, the request contains two important parts:
1.	Payload — The event data in JSON format.
2.	Signature — A security value generated by the server using HMAC SHA256.
Example Webhook Request
POST /webhooks/orders
Content-Type: application/json
X-Webhook-Signature: 8f3a...example-signature
Example payload:
{
  "event": "order.created",
  "orderId": "ORD1001",
  "customerId": "C1001",
  "amount": 150
}
The server creates the signature using a secret key that is shared securely with the receiving application.
Why Signature Verification Is Important
A webhook endpoint should not automatically trust every request it receives. An attacker could send a fake request to the webhook URL.
The receiving application should therefore:
•	Read the raw request body.
•	Use the shared secret key.
•	Calculate an HMAC SHA256 signature.
•	Compare the calculated signature with the signature sent by the server.
•	Process the webhook only when the signatures match.
If the signatures do not match, the application should reject the request.
HMAC Verification Flow
Webhook received
       ↓
Read raw request body
       ↓
Get X-Webhook-Signature
       ↓
Calculate HMAC SHA256 using shared secret
       ↓
Compare signatures
       ↓
Match? ── Yes → Process webhook
       │
       └─ No  → Reject webhook
This verification helps confirm that the webhook was generated using the shared secret and that the received payload has not been modified.
4. HMAC SHA256 Signature Verification
The receiving application can verify a webhook signature by calculating an HMAC SHA256 value from the raw webhook payload and the shared secret. The calculated signature is then compared with the signature sent by the server.
4.1 Node.js Example
The following example uses Node.js to calculate and verify the webhook signature:
const crypto = require("crypto");

function verifyWebhookSignature(payload, receivedSignature, secret) {
  const expectedSignature = crypto
    .createHmac("sha256", secret)
    .update(payload)
    .digest("hex");

  if (expectedSignature.length !== receivedSignature.length) {
    return false;
  }

  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(receivedSignature)
  );
}

// Example
const payload = '{"event":"order.created","orderId":"ORD1001"}';
const receivedSignature = "SIGNATURE_FROM_HEADER";
const secret = "YOUR_WEBHOOK_SECRET";

console.log(
  verifyWebhookSignature(payload, receivedSignature, secret)
);
The application uses the raw payload and shared secret to calculate the expected HMAC SHA256 signature. It then compares the expected value with the signature received in the webhook header.
4.2 Python Example
The same verification can be implemented in Python:
import hmac
import hashlib

def verify_webhook_signature(payload, received_signature, secret):
    expected_signature = hmac.new(
        secret.encode(),
        payload.encode(),
        hashlib.sha256
    ).hexdigest()

    return hmac.compare_digest(expected_signature, received_signature)


# Example
payload = '{"event":"order.created","orderId":"ORD1001"}'
received_signature = "SIGNATURE_FROM_HEADER"
secret = "YOUR_WEBHOOK_SECRET"

print(verify_webhook_signature(
    payload,
    received_signature,
    secret
))
Python uses the hmac and hashlib modules to calculate the SHA256 signature and hmac.compare_digest() to compare the signatures securely.
4.3 Important Security Practices
Developers should:
•	Keep the webhook secret private.
•	Use the raw request body when calculating the signature.
•	Compare the received and calculated signatures securely.
•	Reject requests when signature verification fails.
•	Avoid printing the webhook secret in logs.

5. Error Handling and Testing
Webhook signature verification should be tested before the application is moved to production.
5.1 Invalid Signature
If the calculated signature does not match the signature received from the server, the application should reject the webhook.
Example response:
HTTP/1.1 401 Unauthorized
The application should not process the event because the request could not be verified.
5.2 Missing Signature
If the webhook request does not contain the required signature header, the application should also reject the request.
Missing X-Webhook-Signature header
5.3 Testing Webhook Verification
Developers should test at least these situations:
Test	Expected Result
Valid payload and valid signature	Webhook is accepted
Modified payload	Webhook is rejected
Invalid signature	Webhook is rejected
Missing signature	Webhook is rejected
Incorrect secret	Webhook is rejected
5.4 Troubleshooting
If valid webhooks are being rejected, developers should check that:
•	The correct webhook secret is being used.
•	The raw payload is used when generating the signature.
•	The signature algorithm is HMAC SHA256.
•	The correct signature header is being read.
•	The calculated signature uses the same encoding as the server.
6. Conclusion
Webhook systems allow applications to receive event notifications automatically. Because webhook endpoints are publicly accessible, signature verification is an important security step.
Using HMAC SHA256 with a shared secret allows the receiving application to verify webhook requests before processing them. Developers should implement signature verification, protect the webhook secret, and test both valid and invalid requests.
